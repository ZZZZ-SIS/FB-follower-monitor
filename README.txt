Facebook 专页粉丝增长监控 v6.1（PyQt6）
========================================

当前主要功能
------------
1. PyQt6 现代图形界面，支持自定义背景色和 Windows 暗色主题兼容。
2. Facebook 网页登录后自动采集专页可见粉丝数，并保存 SQLite 历史。
3. “采集 / 提醒间隔”只设置一次，同时用于：
   - 自动采集周期；
   - 增长比较时间窗口；
   - 触发后的重复铃声间隔。
4. 增长提醒只需另外设置“粉丝增长 >= 多少”。
5. 达到提醒条件后会立即响铃，并按“采集 / 提醒间隔”持续重复；点击该专页的“停止”后才停止当前提醒。
6. 提供内置 bell.wav，也可以选择本地音频。
7. 上方删除专页 ID 后，下方当前结果自动移除；不会删除 SQLite 历史。
8. 当前结果中的“专页 ID / 专页名称”支持双击复制。

示例
----
采集 / 提醒间隔：1 分钟
增长阈值：2

含义：
- 每 1 分钟采集一次；
- 比较约 1 分钟内的粉丝增长；
- 如果增长 >= 2，立即提醒；
- 如果没有手动点击该专页旁的“停止”，以后每 1 分钟继续响铃。

第一次使用
----------
1. 完整解压 ZIP。
2. 双击 install_windows.bat 安装 PyQt6 + Playwright。
3. 双击 start_windows.bat。
4. 点击“打开登录浏览器”，在 Edge/Chrome 中正常登录 Facebook。
5. 登录成功后关闭整个浏览器窗口。
6. 输入专页 ID，设置“采集 / 提醒间隔”和增长阈值。
7. 点击“开始自动监控”。

铃声
----
- “内置铃声”：使用 assets\bell.wav。
- “自定义铃声”：可选择 WAV / MP3 / M4A / OGG / FLAC；WAV 最稳妥。
- 点击“试听”可立即测试。

数据位置
--------
Windows: %LOCALAPPDATA%\FacebookFollowerTracker

其中包含：
- fb_follower_tracker.db
- browser_profile\

说明
----
- 软件只读取正常登录后网页上实际显示的数据。
- 不处理或绕过验证码、登录验证、账号限制。
- Facebook 如果只显示 38万 / 17K 这种缩写，软件只能得到约值，因此无法准确检测很小的增长。

【v5.1 新增】
- 顶部“选择背景色”可自定义软件主界面背景颜色。
- 支持任意颜色，并自动调整标题文字明暗以保持可读性。
- 背景色会自动保存，下次打开继续使用。
- “恢复默认背景”可一键回到默认浅灰蓝背景。


【v5.2 暗色系统主题兼容修复】
- Windows 即使设置为“暗色模式”，软件输入框、下拉框、数字框、复选框和表格文字仍保持清晰可见。
- 软件使用独立的浅色控件调色板，不再继承 Windows 暗色主题导致的白字/白底问题。
- 下拉列表、占位文字、禁用控件、选中行等颜色也已统一处理。
- 自定义“背景色”功能继续保留，不影响表单区域的可读性。

【v5.3 专页名称识别修复】
- 修复把“关注 360 人 / 关注 0 人 / 1 人关注”等统计文字误当成专页名称的问题。
- 增加对“关注人数、粉丝数、点赞数、Following”等统计/操作文字的过滤。
- 提高真正名称来源的优先级：og:title、页面标题、H1、指向当前专页的链接、头像 alt/aria-label。
- 降低普通大字体区域的优先级，避免 Facebook 页头的统计信息抢占名称。
- 重新采集后会自动覆盖表格中的旧错误名称；SQLite 历史数据不会删除。

【v5.4 专页名称识别再次重构】
- 不再使用“页面里最大的普通文字”猜专页名称，避免把“全部 / 详细信息 / 通知 / 关注人数”等 Facebook 界面文字当成名称。
- 优先读取页面主内容区中、且不属于导航/标签/菜单/弹窗的可见 H1。
- 第二优先读取专页头像的可访问名称（例如“XXX 的头像 / XXX's profile picture”）。
- 再读取指向当前专页 ID 的自链接、og:title、页面标题和粉丝数附近的身份文字。
- 如果主页面仍无法识别名称，会自动尝试 profile.php?id=专页ID 和 /about 两个 Facebook 官方页面路径，仅用于补取名称。
- 明确过滤“全部 / All / See all / 筛选 / 最近 / 最相关 / 精选”等标签和筛选项。
- 如果最终仍未识别，会在 %LOCALAPPDATA%\FacebookFollowerTracker 下生成 page_name_debug_专页ID.txt，仅包含名称候选和选择器诊断，不保存 Cookie，可用于继续定位页面结构变化。


【v5.5】
- 上方“专页 ID”列表与下方“当前结果”实时同步：从上方删除某个 ID，下方对应结果会立即移除；不会删除 SQLite 历史。
- 如果某个专页正在响铃，而你从上方删除了该 ID，也会同时停止该专页当前提醒。
- “增长提醒”区域新增“待确认提醒”列表，每个触发专页都有独立“🔕 已知，关闭”按钮。
- 未点击关闭时，铃声每 8 秒重复一次；多个专页同时提醒时，列表会分别保留，方便逐个确认。
- 下方结果表的“专页 ID”和“专页名称”支持双击直接复制到剪贴板。


【v5.6 本次新增】
- 修复“待确认提醒”右侧操作按钮字体/图标在部分 Windows 字体环境下显示不完整的问题。
- 操作按钮改为纯文字“停止提醒”，并固定足够宽度和清晰的深色字体。
- 删除固定“每 8 秒重复响铃”的规则。
- 现在提醒触发后，重复响铃间隔直接使用你上方设置的提醒时间窗口：
  例如“1 分钟内增长 >= 2”触发后，未点击“停止提醒”就每 1 分钟响一次；
  “30 分钟内增长 >= 500”则每 30 分钟响一次。
- 每个已触发专页独立记录下一次响铃时间，一直重复到你手动点击“停止提醒”。


【v5.7 本次新增】

- 例如选择“1 分钟”，软件每 1 分钟采集一次，同时按 1 分钟增长判断提醒；触发后未手动停止时，也每 1 分钟重复响铃。
- 增长提醒区域不再出现第二套分钟/小时输入框，只保留“粉丝增长 >= 多少”的阈值。

- 鼠标停留在“停止”按钮上仍会显示完整说明。


【v5.9 本次新增】
- 待确认提醒的操作按钮进一步压缩为单字“停”，固定 38×24，并清除按钮内部额外 padding，避免高 DPI / 全屏下文字被裁切。
- 待确认提醒表中的“专页”名称改为居中显示。
- 下方“当前结果”表中的“专页名称”也改为居中显示；全屏或拉宽窗口时视觉更整齐。
- 两个表格的表头统一居中。

【v6.1 本轮专页静音】
- 点击某个专页的“停”后，该专页在当前这一轮自动监控中后续粉丝再增长也不再响铃、不再弹系统提醒。
- 只有下次重新点击“开始自动监控”时，才会清空本轮已停止的专页列表，恢复提醒。
- “立即采集一次”不会重置已停止的本轮提醒。


【2026-10-06 安全审核修复】
- CSV 导出将疑似公式文本加单引号，数据库原始数据保持不变。
- 网页名称和错误状态按纯文本显示；专页 ID 输入框不接收富文本。
- 浏览器沙箱已启用；不要通过关闭沙箱绕过启动失败，也不要用管理员权限运行。
- POSIX 系统数据目录和浏览器资料目录限制为 0700；Windows ACL 需在目标机器验证。
- 名称诊断 URL 不再保存用户名、密码、查询参数和片段。已有调试文件不自动删除。
- 安装与打包脚本读取 requirements.txt / requirements-build.txt，当前仍沿用原有未固定版本策略。
- requirements-candidate.txt 仅为建议版本基线，尚未接入安装脚本，需开发者确认及 Windows 验证。
- 安全回归测试：python -m unittest discover -s tests -v
- browser_profile 包含登录会话，不能上传、共享或纳入版本控制。若已泄露，应在 Facebook 退出相关会话并重新登录。
